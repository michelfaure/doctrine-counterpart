## Apprentissages méthodo

1. **Sonde matérielle YAML > inférence visuelle GitHub**. Un Claude externe a affirmé "6/6 frontmatters cassés" sur la base du rendu github.com (tableau Markdown au lieu de bloc YAML). `python3 -c "import yaml; yaml.safe_load(...)"` renverse le diagnostic à 11/12 OK. Le rendu d'un host applique sa propre logique de Markdown — le rendu visuel n'est jamais l'autorité matérielle. Confirme R1 + R12 v0.7. Codifié en mémoire user-scope `feedback_external_ai_visual_rendering_not_material.md`.

2. **Empirisme intégré : la doctrine se mesure et la mesure révèle ses failures**. M7 a exposé 92 commits consécutifs sans session log, validant matériellement que R15 amendée v0.7 était nécessaire et pas encore opérationnelle. La doctrine qui mesure son propre non-respect produit un signal autocritique fort. Pattern réutilisable : ajouter une métrique pour chaque amendement de règle, mesurer la baseline pre-déploiement, mesurer post — l'écart révèle l'efficacité réelle du déploiement.

3. **Cleanup public irréversible mérite arbitrage explicite avant exécution**. Michel Faure a paniqué quand il a réalisé que rembrandt-samples contenait des paths personnels — j'aurais dû soulever ce point en amont, avant l'option A "sync chiffres" qu'il avait validée. Pattern : pour toute action publique (push GitHub public, repos visibles), faire un audit fuite matériel AVANT de demander validation, et présenter le threat model en options (crawler / reproductibilité / fiscal). Michel Faure a tranché niveau A après avoir vu les options ; sans ce détour, la décision aurait été aveugle.

4. **Le protocole /close-session lui-même détecte du drift**. Le compte ADR dans CLAUDE.md ("76+") différait de 3% du filesystem (74). Pas critique, mais c'est le pattern même que la doctrine prêche. Si /close-session n'avait pas exécuté l'Étape 3 (vérif anti-stale), le drift aurait été publié sur GitHub public sans détection. Le protocole se valide en miroir : il attrape ce qu'il prêche d'attraper.
