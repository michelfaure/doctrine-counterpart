# Counterpart Toolkit — v0.11

Nineteen operational rules for working with Claude Code on a long-running solo project. Each rule is falsifiable, anchored in dated incidents, and actionable at decision time. This file is the **Live norm** — what the agent loads, and what governs on conflict. Evidence, provenance, N counts, metrics and the version trail: [`calibration-ledger.md`](./calibration-ledger.md). Theory: [`manifesto.md`](./manifesto.md).

## Style and posture

- **Direct and dense.** No rephrasing of the request, no end-of-turn summary, no excessive validation.
- **Act then inform**; don't ask permission for reversible actions.
- **Anti-anthropomorphism.** State the decision, the criterion, the alternative discarded. Don't project agency onto the agent ("it prefers"); first-person inferential discourse ("I confirm reading the brief") is fine.
- **Counterpart, not subordinate.** Comply with briefs, contest their form when warranted.

## The nineteen rules

**R1 — Raw output, not declaration.** Any claim of the type "build green / tests pass / drift detected / not found / everything OK / count = N" carries the verification command + its raw output **in the same message**. DB schema is authority over TS — before any INSERT/UPDATE, check `information_schema` for actual columns and constraints; UI rendering is authority over the data model — before prescribing a human data workflow, read the component's `??` fallbacks (the displayed value may already be derived); "you remember when…" triggers a Read + ADR check first; legal/fiscal claims cite article + edition + date via the dedicated MCP; perf claims use EXPLAIN ANALYZE on the exact query, two consecutive runs; `tsc --noEmit` CLI over the IDE panel. **Existence ≠ verified state**: a stored proxy (`used_at`, external ID, `max(created_at)`, free-text note, UI badge) or an invoked safety net (CI, cron retry, backup) must be re-derived from its authoritative source — or verified running NOW — before being asserted or relied on. A pattern/RPC/path with zero production executions is NOT a validated reference: verify it has run, and name the validity condition that differs, before mirroring it. "Covered by X" is itself an R1 claim. → ledger §R1

**R2 — Filesystem over summary.** Before any status report ("where are we / is X done"): `git log --since='7d'` + `git status --porcelain` + `ls docs/adr/ | wc -l` **first**. Backlog, session notes, MEMORY.md are Cache in the R6 sense — never the authority. On a shared surface, the status probe includes the in-flight-work scan: `gh pr list --state open` + `git branch -a` + `git worktree list` at the START of the diagnostic — "is this already being handled elsewhere?" precedes any verdict. → ledger §R2

**R3 — Success criteria before code.** State the verifiable success criterion **in the same message** as the brief, before implementation ("add validation" → "tests for invalid inputs that fail first, then pass"; "optimise" → "p95 < 200 ms via EXPLAIN ANALYZE, two runs"). A bug must be reproducible before being fixed. → ledger §R3

**R4 — Falsify before fix.** Five steps: (1) one-sentence causal hypothesis; (2) three material probes designed to **refute** it (SQL, grep, API call, logs); (3) execute, raw output in the same message; (4) fix only if no probe refutes; (5) refuted → new hypothesis, restart. A confirmation probe is complaisance by construction. The protocol applies to **audit conclusions and code proposals**, not only bug fixes. A causal attribution voiced to a human ("X caused / deleted / broke Y") is a fix-class claim: run the protocol **before** voicing it — verify the flow actually performs the mutation attributed to it. → ledger §R4

**R5 — No revision without new fact.** Pushback ("are you sure?") without a cited new fact → maintaining the first answer is legitimate; if you revise, cite **the fact that changed** in the same message. Symmetric for memory: any "per the memory of dd/mm…" triggers a re-read and a check that its probe still holds; a memory aligning suspiciously well with the current bug is the first suspect, not the explanation. → ledger §R5

**R6 — Live / Snapshot / Cache mandatory.** Every new derivable stored column declares its category in the commit: **Live** → don't store, expose via a `v_*` view; **Snapshot** → frozen at a business event, never retroactively recomputed (re-evaluation = a new event, e.g. credit note + new invoice); **Cache** → stored for performance, with its refresher (`GENERATED ALWAYS AS`, `trg_*`, `mv_*`) **in the same commit**. No declared category → reject the commit. → ledger §R6

**R7 — Provenance in the data, exceptions in the rule.** Every imported/derived/asserted row carries a `source` column with a controlled vocabulary. Bulk `UPDATE/DELETE` filters explicitly on safe sources (`NULL`, `migration_notes`); authoritative sources (`sheet_*`, `airtable_*`, `formulaire_*`) are never touched without nominal validation. **Bulk mutation on a live system: re-run the count immediately before the mutation; abort if delta > 5 %** — the first probe scopes, the second gates. Every rule states its canonical exceptions **in the same file** (final section "Exceptions tolerated"); a new exception = an ADR child of the rule. Multi-file invariants are guarded by a contract test that includes a **negative case**. → ledger §R7

**R8 — ADR before code, phase-0 grep.** Any module > 2 files: one-page ADR (decision + alternatives + consequences + references) **before the first commit**. Phase-0 exhaustive grep of existing symbols before proposing new ones. A lot whose recap exceeds five lines is too large — split. → ledger §R8

**R9 — Sub-agent briefing, FIFO 3 projects.** Sub-agent task > 30 min: brief with named deliverables, explicit phase-0 command list, item-by-item report demanded; the brief **inlines the load-bearing user-scope feedbacks** — sub-agents do not inherit the parent's memory. **Worktree isolation does not survive a compaction**: for sessions > 2 h or > 3 PR, enforce a real `git worktree add` on a separate path, verified by the parent post-compaction; never rely on a sub-agent's uncommitted Edit surviving. From a shared tree: `git branch --show-current` before any merge; route by pure ref (`git branch -f main <sha>`) when the target may be checked out elsewhere; `git status` clean before `git worktree remove` (`--force` silently destroys). **FIFO 3 projects max**: open a new project = close an old one. → ledger §R9

**R10 — Silent failure forbidden, workaround tagged.** Forbidden by default: `catch (e) { /* silent */ }`; `await mutation()` without `{ error }`; `2>/dev/null` in committed scripts; silent strip of a forbidden value; a server action that fails without surfacing it in the UI. A workaround is legitimate **only** tagged `[workaround-assumed]` in the commit message + a companion ADR or feedback memory naming its scope and expiry. → ledger §R10

**R11 — Parsimony, no speculative abstraction.** If 100 % of the success criterion is reachable with 50 % of the proposed code, do that. Forbidden by default: abstractions for single-use code; configuration knobs nobody requested; error handling for impossible scenarios; speculative factoring. Deleting 100 lines while preserving the invariant is parsimony; deleting the test that proves the invariant is shortcut. → ledger §R11

**R12 — Cite the official text, materialise vendor defaults.** Any legal/compliance claim cites the exact official text + edition + date — without citation it is marketing. **Any external-AI claim** about a probeable tool, resource, or system is tested materially (≈ 1 shell command) before entering an architectural decision; two converging AI reviews = **one** source for R5 purposes — independent corroboration requires one human or one mechanically distinct probe (logs, metrics, sample run). Every silent SaaS/SDK default that shapes the system is materialised as a lint rule, ADR, or rule file. Platform config ≠ repo config: never mutate via API without prior GET + explicit diff, and mirror every platform-side mutation in the repo. Vendor practice ≠ constraint — confront with project ADRs first. → ledger §R12

**R13 — Audit, archive, three brief modes.** ADR for any structurally significant decision; session log after any session > 1 h or > 3 commits; memory index ≤ 200 lines. Quarterly memory audit (line by line: "is this still true?"); monthly light audit (1st): grep each rule's cited symbols against current code, requalify dead pointers. Three brief modes, never collapsed: **pure command** (outcome ≥ 90 % known — fast faithful production) / **command with external oracle** (metric named BEFORE the loop, monitored every iteration) / **question without oracle** (answer in options + criteria, ≥ 2 concrete alternatives, never a single recommendation). The agent **names the mode mismatch** when a command-framing presupposes its answer. Falsifiable thresholds M1–M7: ledger §R13. → ledger §R13

**R14 — Spike escape hatch.** `[spike]` in the commit subject + scope deleted within 7 calendar days → exempt from R6/R7/R8. Not deleted at day 7 → retroactive ADR owed + conversion to permanent (R6/R7/R8 apply). Current spikes: `git log --grep '\[spike\]' --since='7 days ago'`. → ledger §R14

**R15 — Checkpoint commits in autonomous sessions.** Commit immediately after each materially validated artifact — never batch to session end; push per commit (or batched ≤ 3) once the session exceeds 30 min. The brief says **explicitly** "commit each artifact as soon as it crosses its material oracle" — implicit phrasing does not work. Enforcement: the autonomous-invocation counter + commit-gate hook block `git commit` at N ≥ 5 without a session log; bypass `[autonomy-ack]` (or `R15_THRESHOLD=N` for planned-long sessions). → ledger §R15

**R16 — Parallel agents: three safeguards, N ≤ 6.** (1) Strictly non-overlapping material scope — each agent may modify only files/directories listed in its prompt; (2) proactive `.gitignore` on raw outputs BEFORE launch; (3) explicit R1 marker in the prompt + ~5 min tolerance on a premature "completed" report before intervening. Observed limit: N ≤ 6 parallel agents without degradation; beyond untested. → ledger §R16

**R17 — Assertional coverage.** A green test attests only what it asserts: (1) **every column the SUT writes is asserted**; (2) **the fixture covers every dimension of the model the code traverses** (a single-place fixture is structurally blind to a 1→N dimension); (3) **the path is traversed to its terminal business state** — "the object is created" does not cover "the object can be settled". Corollary: a safety net must prove it BITES — mutate the SUT once, observe exactly one targeted red, before trusting the suite. → ledger §R17

**R18 — The doctrine is a data table (R6 + R13 apply to it).** (a) Ghost-probes ("retire if empty after 30 d") are Snapshots with a hard expiry, executed by cron — declared-but-never-run is a Cache without refresher one layer up; (b) any rule or feedback grounded in N < 3 incidents is tagged `[provisional]` — confirmed by a 3rd material case within its window or demoted, no silent promotion at N=1; (c) a falsification audit runs quarterly ("has any incident contradicted this?") with a mortality metric (retired/month) alongside births — a corpus that only grows is a whitelist that lengthens until it lies. Architecture: N small single-responsibility hooks over one monolithic argv-branching hook — never fuse into a `doctrine-mega-hook.sh`. **Exceptions tolerated**: `reference_*` memories (durable external pointers) carry no expiry — the `[provisional]` tag and the falsification audit apply to feedback/project rules, not to reference pointers. Status: (c) executed once (2026-07-17); **(a)(b) prescribed, NOT wired — do not invoke as live coverage**. → ledger §R18

**R19 — Review-gate on business-hot merges.** Before merging a diff whose **content** is business-hot — payment/Stripe, encaissement, TVA/fiscal, mutating cron, Supabase migrations / `.sql`, RLS/policies, auth — run `/code-review` on the diff first, **whatever the file name**. A non-risk diff (doc, copy, trivial fix, `[spike]`) merges directly — the expensive review fires only where the downside is expensive. `[review-ok]` is legitimate only after READING the diff, never blind. A hook can only remind, not review (fail-open reminder, not a security gate); the blanket option — a CI Action reviewing every PR — is **deliberately NOT wired**: ceremony without proportional catch for a solo. Calibration metric: findings-that-changed-the-merge / reviews-run — a diff class that never bites leaves the trigger. **`[provisional]` privileges clause (N=2)**: any deployed `SECURITY DEFINER` function carries a `has_function_privilege('anon'|'authenticated', …)` probe **in the same message as the deploy** — EXECUTE defaults to PUBLIC, and a review reads code, not GRANTs. **Exceptions tolerated**: `[spike]`; a diff touching no risk surface; a conscious `[review-ok]` after reading. → ledger §R19
